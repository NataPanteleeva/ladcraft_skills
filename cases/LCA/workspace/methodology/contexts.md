# Каталог контекстов (видов документов)

Агент: сопоставь формулировку пользователя со **slug**.  
Правила: `/workspace/rules/{slug}/RULES.md`  
Образец стиля: `/workspace/style/{slug}/sample.md` (если файл есть).

**Запрос «какие есть правила / стили / шаблоны»:** ответь списком **slug из этой таблицы** (и папок `rules/` / `style/` при проверке `ls`). Не дополняй вымышленными пунктами.

| slug | Ключевые слова в запросе пользователя | Папка правил |
|------|----------------------------------------|--------------|
| `general` | не указан вид; «нейтрально»; «просто текст» | `rules/general/` |
| `letter` | письмо, служебная записка, обращение, исходящее | `rules/letter/` |
| `contract` | договор, соглашение, приложение к договору, оферта | `rules/contract/` |
| `announcement` | объявление, новость, анонс, пост, уведомление | `rules/announcement/` |
| `report` | отчёт, служебный отчёт, итоги периода | `rules/report/` |
| `yoda` | «как Йода», «в стиле Йоды», «учимся говорить как Йода», инверсия Йоды | `rules/yoda/` |

**Стилистика vs вид документа:** `yoda` — **вариант стиля** (порядок слов), не тип делового документа. Если пользователь явно просит стиль Йоды — бери slug `yoda` (и `style/yoda/sample.md`), даже если исходный текст — письмо или абзац отчёта. В ответе пользователю **не** перечисляй правила №1–3 и не пиши «логику применения», пока не попросят.

**Если не уверены** — `general` и одной фразой предложите уточнить вид документа (это влияет на правила, ФТ-02).

Чтобы добавить новый вид: создайте `rules/{slug}/RULES.md`, строку в этой таблице, при необходимости `style/{slug}/sample.md`.
