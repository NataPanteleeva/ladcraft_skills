# Создание навыков через веб-интерфейс

Это руководство описывает, как создать приложение-навык (skill application) в маркетплейсе платформы через веб-интерфейс — без написания скриптов и API-запросов вручную.

> **Смотрите также:** [Руководство по написанию функций-инструментов](skill-function-guide.md) — описывает API функций `handler`, доступный `state`, OAuth-паттерны и ограничения ресурсов.

---

## Что такое навык (skill)

**Навык** — это приложение в маркетплейсе, которое добавляет агенту новые возможности. Навык состоит из:

- **Системного промпта** (skill text) — инструкция для агента: когда и как применять навык.
- **Инструментов** (tools) — исполняемые функции на JavaScript, которые агент вызывает для работы с внешними API, хранилищем и т. д. Каждый инструмент работает изолированно в Firecracker VM.
- **Виджетов** (widgets, опционально) — HTML/EJS-шаблоны для красивого отображения результата инструмента в чате.

---

## Открытие формы создания

1. Перейдите в **Маркетплейс** (`/marketplace`).
2. Нажмите кнопку **«+ Создать навык»** (или аналогичную кнопку добавления).
3. Откроется модальное окно **«Создание навыка»**.

---

## Поля формы

### Раздел: Основное

| Поле | Обязательно | Описание |
|---|---|---|
| **Название** | да | Уникальное короткое имя. Отображается в карточке маркетплейса. |
| **Описание** | да | Краткое описание навыка — что умеет, для кого. |
| **Системный промпт (skill)** | да | Markdown-текст. Инструкция для агента: когда включать навык, как работать с его инструментами, какой формат ответа ожидается. |
| **Версия** | нет | Семантическая версия, по умолчанию `1.0.0`. В режиме редактирования поле недоступно. |
| **Категория** | да | Выбор из списка. Используется для фильтрации в маркетплейсе. |
| **Иконка (URL)** | да | Ссылка на изображение иконки (png/svg). Должна быть валидным URL. |
| **Обложка (URL)** | да | Ссылка на изображение для карточки. Должна быть валидным URL. |
| **Лицензия** | нет | Только при создании. Например: `MIT`, `Apache-2.0`. |
| **Автор** | нет | Только при создании. Имя или никнейм автора. |
| **Теги** | нет | Список строк. Используется для поиска. Добавляются по одному. |

### Раздел: Инструменты (Tools)

Навык может содержать от нуля до нескольких инструментов. Нажмите **«+ Добавить инструмент»**, чтобы раскрыть редактор.

Каждый инструмент — это карточка со следующими вкладками/секциями:

#### Основная информация инструмента

| Поле | Обязательно | Описание |
|---|---|---|
| **Название** | да | Машинное имя инструмента (snake-case или kebab-case). Агент ссылается на него по этому имени. |
| **Описание** | да | Подсказка для агента — когда и зачем вызывать этот инструмент. |

---

#### Capabilities (разрешения)

Список платформенных возможностей, необходимых инструменту. Каждый элемент содержит:

| Поле | Описание |
|---|---|
| **Тип** | Тип capability: `gitlab`, `key-value-storage`, `notification` и др. Выбирается из списка, доступного на платформе. |
| **Операции** | Что разрешено делать: `read`, `write`, `Get`, `Set` — зависит от типа. |
| **Scope** | `$APP` — разрешение на уровне приложения, `$USER` — разрешение запрашивается у каждого пользователя отдельно. |

**Пример:** если инструмент работает с GitLab от имени пользователя, добавьте capability:
- Тип: `gitlab`, Операции: `read, write`, Scope: `$USER`

---

#### Environment — переменные окружения

Переменные окружения делятся на два типа:

**App-переменные** (одинаковы для всех пользователей):

| Поле | Описание |
|---|---|
| **Ключ** | Имя переменной (`OPENAI_API_KEY`). Должно быть уникальным. |
| **Значение** | Значение по умолчанию или секрет уровня приложения. |

Доступны в функции как `state.environment.app.OPENAI_API_KEY`.

**User-переменные** (задаются каждым пользователем при установке навыка):

| Поле | Описание |
|---|---|
| **Ключ** | Имя переменной (`GITLAB_TOKEN`). |
| **Заголовок** | Понятное название для формы установки навыка пользователем. |
| **Формат** | Тип значения: `string`, `number`, `boolean`, `uri`, `email`. |

Доступны в функции как `state.environment.user.GITLAB_TOKEN`.

---

#### Resources — ресурсы VM

| Поле | Диапазон | По умолчанию | Описание |
|---|---|---|---|
| **CPU** | 0.1 – 1.0 | 0.5 | Доля процессорного времени. |
| **Memory** | 64 – 256 MiB | 128 | Оперативная память VM. |
| **Timeout** | 1 – 3600 с | 30 | Максимальное время выполнения функции. |

**Разрешённые хосты сети** — список доменов, к которым может обращаться `fetch()` внутри функции. Запросы к хостам вне списка блокируются на уровне iptables.

Пример хостов для GitLab-инструмента: `gitlab.com`, `glab.lad24.ru`.

---

#### Schemas — схемы входа/выхода

**Input Schema** (обязательно) — JSON Schema объекта `params`, который агент передаёт в инструмент. Используется для валидации и генерации подсказок агенту.

Пример:
```json
{
  "type": "object",
  "properties": {
    "city": {
      "type": "string",
      "description": "Название города"
    }
  },
  "required": ["city"],
  "additionalProperties": false
}
```

**Output Schema** (необязательно) — JSON Schema результата, который возвращает функция. Помогает агенту корректно интерпретировать ответ.

---

#### Function — функция-обработчик

JavaScript-код, выполняемый в изолированной Firecracker VM на Node.js 22. Должен объявлять функцию `handler`:

```javascript
async function handler(state, params) {
  // params — входные параметры (описаны в Input Schema)
  // state.environment.app.* — app-переменные
  // state.environment.user.* — user-переменные
  // Глобальный fetch доступен
  const data = await fetch('https://api.example.com/endpoint', {
    headers: { Authorization: `Bearer ${state.environment.app.API_KEY}` },
  }).then(r => r.json());

  return { result: data };
}
```

> `import` / `require` не поддерживаются. Используйте только глобальный `fetch` и встроенные API Node.js 22.
> Подробнее — в [руководстве по функциям](skill-function-guide.md).

---

#### Widget — виджет (необязательно)

EJS-шаблон для рендеринга результата инструмента в интерфейсе чата. Переменная `result` содержит то, что вернула функция.

```html
<% const items = result.issues || []; %>
<ul>
  <% items.forEach(function(item) { %>
    <li><a href="<%= item.web_url %>" target="_blank">#<%= item.iid %> <%= item.title %></a></li>
  <% }); %>
</ul>
```

Если виджет не задан — результат отображается в виде текста/JSON.

## Пошаговый пример: простой навык без инструментов

Навык с системным промптом и без инструментов — это «режим агента»: он меняет поведение агента в диалоге, не вызывая внешних API.

**Пример: навык «Код-ревьюер»**

1. Откройте форму создания навыка.
2. Заполните:
   - **Название:** `code-reviewer`
   - **Описание:** `Проверяет код и оставляет комментарии по best practices`
   - **Системный промпт:**
     ```markdown
     # Code Reviewer

     Ты — опытный code reviewer. При получении кода:
     1. Выяви потенциальные баги и ошибки
     2. Проверь читаемость и стиль
     3. Предложи улучшения
     Пиши по-русски. Будь конкретным: указывай строки и предлагай исправления.
     ```
   - **Версия:** `1.0.0`
   - **Категория:** `development`
   - **Иконка:** `https://...`
   - **Обложка:** `https://...`
3. Раздел **Инструменты** оставьте пустым.
4. Нажмите **«Создать»**.

## Пошаговый пример: навык с инструментом (погода)

**Задача:** навык запрашивает текущую погоду по названию города через открытое API.

### Шаг 1. Основные поля навыка

- **Название:** `weather`
- **Описание:** `Показывает текущую погоду по названию города`
- **Системный промпт:**
  ```markdown
  # Weather Skill
  Когда пользователь спрашивает о погоде — вызови инструмент `get-weather` с названием города.
  Ответ сформулируй кратко и по-русски.
  ```
- **Категория:** `utilities`

### Шаг 2. Добавьте инструмент

Нажмите **«+ Добавить инструмент»**.

**Название:** `get-weather`
**Описание:** `Получает текущую погоду для указанного города`

### Шаг 3. Capabilities

Этот инструмент не требует платформенных capabilities. Оставьте список пустым.

### Шаг 4. Environment

App-переменные и user-переменные не нужны — API погоды открытый.

### Шаг 5. Resources

- **CPU:** `0.2`
- **Memory:** `64`
- **Timeout:** `15`
- **Хосты сети:** `wttr.in`

### Шаг 6. Input Schema

```json
{
  "type": "object",
  "properties": {
    "city": {
      "type": "string",
      "description": "Название города на английском"
    }
  },
  "required": ["city"],
  "additionalProperties": false
}
```

### Шаг 7. Function

```javascript
async function handler(state, params) {
  const { city } = params;
  const url = `https://wttr.in/${encodeURIComponent(city)}?format=j1`;

  const response = await fetch(url, {
    headers: { 'User-Agent': 'platform-skill/1.0' },
  });

  if (!response.ok) {
    throw new Error(`Weather API error: ${response.status}`);
  }

  const data = await response.json();
  const current = data.current_condition[0];

  return {
    city,
    temp_c: current.temp_C,
    feels_like_c: current.FeelsLikeC,
    description: current.weatherDesc[0].value,
  };
}
```

### Шаг 8. Widget (опционально)

```html
<% const w = result || {}; %>
<div style="font-family: sans-serif; font-size: 14px; padding: 12px; border-radius: 8px; background: #f0f9ff; border: 1px solid #bae6fd;">
  <strong><%= w.city %></strong> &mdash; <%= w.description %><br>
  🌡 <strong><%= w.temp_c %>°C</strong>, ощущается как <%= w.feels_like_c %>°C
</div>
```

### Шаг 9. Сохранение

Нажмите **«Создать»**. Навык появится в маркетплейсе и будет доступен для установки агентам.

## Пошаговый пример: навык с user-переменными (GitLab)

Если инструмент требует персонального токена от каждого пользователя, используйте **user-переменные**.

### Environment → User-переменные

| Ключ | Заголовок | Формат |
|---|---|---|
| `GITLAB_TOKEN` | `GitLab Personal Access Token` | `string` |
| `GITLAB_BASE_URL` | `GitLab API URL (необязательно)` | `string` |
| `GITLAB_PROJECT_ID` | `GitLab Project ID (необязательно)` | `string` |

### Capabilities

| Тип | Операции | Scope |
|---|---|---|
| `gitlab` | `read, write` | `$USER` |

### Хосты сети

`gitlab.com`, `glab.lad24.ru`

### Использование токена в функции

```javascript
async function handler(state, params) {
  const token = state.environment.user.GITLAB_TOKEN;
  const baseUrl = state.environment.user.GITLAB_BASE_URL ?? 'https://gitlab.com/api/v4';

  if (!token) {
    throw new Error('GITLAB_TOKEN is required');
  }

  const res = await fetch(`${baseUrl}/projects/${params.project_id}/issues`, {
    headers: { 'PRIVATE-TOKEN': token },
  });

  return await res.json();
}
```

## Частые ошибки

| Ошибка | Причина | Решение |
|---|---|---|
| Функция не выполняется | Хост не в списке `network.hosts` | Добавьте домен API в раздел «Хосты сети» |
| `state.environment.user.X is undefined` | Пользователь не заполнил переменную | Проверьте, что переменная добавлена в User-environment и пользователь прошёл установку |
| Невалидный JSON в Input Schema | Синтаксическая ошибка | Проверьте JSON в редакторе — он должен быть валидным объектом с `"type": "object"` |
| Таймаут | `timeout` слишком мал | Увеличьте Timeout в Resources (для OAuth-потоков может потребоваться 120–300 с) |
| `import`/`require` не работает | Ограничение среды выполнения | Используйте только глобальный `fetch` и `node:http` через динамический `await import('node:http')` |

## Советы

- **Системный промпт** — ключевое место. Чётко укажите агенту: когда вызывать инструменты, какие параметры передавать и как интерпретировать результат.
- **Input Schema** — чем точнее описаны параметры с `description`, тем лучше агент понимает, что передавать в инструмент.
- **Widget** — используйте только для результатов с понятной визуальной структурой (списки, карточки). Для простых текстовых ответов виджет не нужен.
- **Timeout** для OAuth-навыков ставьте 120–300 секунд: пользователю нужно время, чтобы пройти авторизацию в браузере.
- **Версионирование:** при обновлении навыка версия не меняется через форму — это делается через API. Форма позволяет задать версию только при создании.
