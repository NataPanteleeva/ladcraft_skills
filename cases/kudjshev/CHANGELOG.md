# Changelog

Все заметные изменения в bundle `cursor_ladcraft` описываются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии следуют [Semantic Versioning](https://semver.org/lang/ru/).

## [0.6.0] — 2026-04-22

### Добавлено

- **Канонизация навыков на диске при работе dev-server**:
  - при чтении папки навыка `dev-server` приводит содержимое к каноническому формату хранения (в т.ч. native `handler`, согласованные meta/скрипты);
  - перед записью нормализованной версии создаётся **резервная копия** в `skills/.skill-backups/<skill-name>/<timestamp>/` (см. `dev-server/src/skill-folder-writer.ts`);
  - если нормализация не удалась, dev-server **пытается откатить** папку из backup (чтобы не оставлять “полу-сломанное” состояние).
- **Аудит публичного контракта + совместимости**:
  - фоновый compatibility audit (через `dev-server/src/compatibility-audit.ts`) формирует отчёты в `skills/.audit/builder-audit.json` и `skills/.audit/builder-audit.md` (и поднимает human-readable issues в web-ui);
  - отдельно проверяется согласованность **инструкций bundle** (например, отсутствие legacy-формулировок/ссылок, которые contradict текущему контракту).
- **Валидация и “блокировка деплоя” в web-ui**:
  - отчёт валидатора с ошибками/предупреждениями;
  - кнопка **«Копировать ошибки»** копирует готовый текст отчёта в буфер обмена, чтобы **вставить в чат с агентом** (авто-интеграции с агентом в UI нет — только clipboard).
- **Миграция старых папок + карантин**:
  - при конфликте “legacy-нормализованное имя” vs “каноническое exact-name” лишняя копия уходит в `skills/.legacy-conflicts/` (см. `dev-server/src/local-skill-registry.ts`).

### Изменено

- **Sync с Ladcraft: меньше ложных “конфликтов” local vs server**:
  - сравнение payload теперь **семантическое**, а не “байт-в-байт”: игнорируется форматный шум (отступы, порядок `default_capabilities`, дефолтные `resources`, несущественные различия виджетов, связанные с путями/именами файлов), который появляется после roundtrip через API Ladcraft;
  - UI: баннер “версии отличаются” поднят ближе к сценарию публикации/редактора, чтобы не терялся внизу экрана.
- **Операционные инструкции приведены к единому “канону Ladcraft + cursor_ladcraft”**:
  - `mcp_instructions.md` остаётся **router-инструкцией**; reference-доки в `docs/ru/` — подтверждение формата и pre-publish review;
  - `skills/` в README явно **не** считается эталонной библиотекой: там могут встречаться legacy/конфликтные паттерны, их используют для аудита, а не как шаблон “как надо”.
